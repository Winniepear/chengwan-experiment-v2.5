# R9上线前核验表

## 材料（由研究负责人签字，不是程序自动判定）

□ 24条评论等于用户确认稿；四组共同事实、昵称、头像、顺序保持。
□ 城市简介纯文字，无图片与标签；帖子保留原三图/标签和原松弛文案。
□ G1中点目标、G2/G3的P/D接近及A区分、G4担忧低掌控均由独立新样本检查。
□ 很平静—很激动及解释完成认知访谈，不能只因文字口语化就视为有效。
□ 主要结果和self PAD不用于挑选“更显著”的材料；无按操纵正确与否删人。

## 程序（先测试站点/预览，不接触旧生产数据）

□ npm run build和npm test通过。
□ 生产Netlify构建与SDK依赖安装成功；确认实际运行版本与锁文件。
□ /api/health显示R9/PRETEST-W2（基础健康并非数据库写入证明）。
□ 正确ADMIN_TOKEN能进入/admin，错误令牌不能导出。
□ /api/admin/health可连接数据库，完整测试问卷可保存与导出。
□ 测试G1—G4六条评论；刷新不改变已分组；高并发配额锁在目标环境专项检查。
□ 开放描述单独一页、可空、限1200字符、后面才显示评论PAD和类别题。
□ 所有1—7题默认不预选答案，A解释在正确位置。
□ 选择风险“有”才显示追问，值仍为0/1。
□ CSV包含comment_feeling_open和原有分数；不将新数据标为R8；不删除旧数据。
□ iPhone、Android、微信内置浏览器实机完成一次全流程，检查图/头像加载与保存重试。
□ 文档、配置、哈希、部署ID、配额与日期归档；生产只发固定正式站点URL。
